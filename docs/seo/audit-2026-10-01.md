- Origin: `src/app/layout.tsx:35` (`template: "%s · Form5472 Prep"`), reached via `title: post.title` at `src/app/(marketing)/blog/[slug]/page.tsx:55` (post titles themselves are 40-60 chars; the 16-char suffix pushes 130 over 60).
- Fix: in `blog/[slug]/page.tsx:55` use `title: { absolute: post.title }` (the pattern `[seoSlug]/page.tsx:143` and `(marketing)/page.tsx:145` already use); this alone clears 107 of 130. The remaining 23 need a shorter `title:` in their frontmatter (`content/blog/*.md` or the admin Post row). Alternative: shorten the suffix to " | F5472" in `layout.tsx:35`.

### S2. Brand written into the page title AND appended by the template (double brand, 4 URLs)
- Origin: `about/page.tsx:10`, `ein/apply/layout.tsx:12`, `itin/apply/layout.tsx:10` set `title: "... Form5472 Prep"` while the layout template adds it again; the partner-program blog post has the brand in its own title.
- Fix: drop the brand from those strings (template supplies it), or wrap in `{ absolute: ... }`. Note `pageMeta()` receives the same string for og:title, so keep og title branded only if desired.

### S3. Root layout canonical "/" leaks into any page that sets no `alternates`
- Origin: `src/app/layout.tsx:43-46` (`alternates: { canonical: "/" }`). `/partner/sign-in` (`src/app/partner/sign-in/page.tsx:8-11`, no `pageMeta`) therefore canonicalises to the homepage. It is noindex today, so impact is low, but any new page without `pageMeta()` will inherit a canonical pointing at "/" (and the homepage's own canonical renders without the trailing slash).
- Fix: delete the `canonical: "/"` line at `layout.tsx:44` (keep `types`), since every public page already passes through `pageMeta()` (`src/lib/seo.ts:63-79`); add `pageMeta`/own canonical only where a page is indexable.

### S4. No /blog/topics index route, but 280 children exist
- Origin: `src/app/(marketing)/blog/topics/` contains only `[tag]/page.tsx`; there is no `topics/page.tsx`. `/blog/topics` returns 404.
- Fix (minimal): add `{ source: "/blog/topics", destination: "/blog", permanent: true }` to `next.config.mjs:4-10`. Better: a real `topics/page.tsx` listing indexable tags (uses `buildTagIndex`).

### S5. Tag-page generation: duplicate slug aliases and thin indexable pages
- Origin: `src/lib/blog-tags.ts:23-24` maps both `non-resident` and `nonresident` to the same label (duplicate title, near-duplicate pages, both indexable and in the sitemap, `sitemap.ts:63-71`); `blog-tags.ts:7` `MIN_INDEXABLE_TAG_POSTS = 3` lets 23 tag pages of 168-288 words into the index and sitemap.
- Fix: add a tag alias map in `tagSlug()` (`blog-tags.ts:42-44`) so `nonresident` -> `non-resident`, plus a permanent redirect in `next.config.mjs` for the old slug. Raise `MIN_INDEXABLE_TAG_POSTS` to 5 (or add an intro paragraph per tag); `sitemap.ts:65` and `topics/[tag]/page.tsx:15,35` already key off that constant. Tag descriptions are a single template (`topics/[tag]/page.tsx:24`, <70 chars for the 195 small tags): lengthen the template if these stay indexable.

### S6. Landing-page related-links never reach 7 pages (orphans)
- Origin: `getRelatedSlugs()` at `src/lib/landing-pages.ts:3090-3123` returns at most 4 slugs and fills explicit `relatedSlugs` and cluster mates first. The vendor pages (`clemta-form-5472` :2705, doola, firstbase, northwest-registered-agent, startglobal, zenind) are in no cluster/explicit list, and `form-5472-fax-number` (:2000, cluster `logistics` :3049-3053) is always crowded out. Nothing else (nav, footer, /blog) links them.
- Fix: add a "Compare providers" cluster to `TOPIC_CLUSTERS` (:3027) and raise `limit` to 6 at the `[seoSlug]/page.tsx` call site (or add a footer/hub link list of all indexable landing slugs).

### S7. Redirect semantics at the apex
- Origin: not in the repo (no host redirect in `next.config.mjs`, `vercel.json`, or `src/middleware.ts`); it is the Vercel project's domain setting for `form5472prep.com` -> `www`. It returns 307 (temporary) instead of 308 on https, and http apex chains 308 (to https apex) then 307 (to www).
- Fix: Vercel dashboard > Project > Domains > edit `form5472prep.com`, set redirect to www with status 308 (Permanent). The two-hop http chain is a Vercel limitation once the apex redirect is 308; acceptable. `/partner` 307 -> `/partner/sign-in` is a Next `redirect()` in an auth gate and is fine (noindex).

### S8. Over-long descriptions on 4 indexable pages and a sitemap that says nothing true about freshness
- Descriptions: `landing-pages.ts:2004` (fax-number, 162), `form-5472-late-filing-checker/page.tsx:32-33` (173), `llc-annual-fees-by-state/page.tsx:15-16` (176), `content/blog/form-5472-philippines-residents-us-llc.md:3` (170). Trim to <= 155 chars.
- Sitemap: `src/app/sitemap.ts:13,18-43,69-75` sets `lastModified: now` for all static and landing URLs, so every lastmod equals the build time; also `/cookies` (indexable, `cookies/page.tsx`) is absent from the `staticUrls` list (`sitemap.ts:18-41`). Fix: use `CONTENT_LAST_REVIEWED`/`page.updated` (`seo.ts:18`) instead of `now`, and add `/cookies`.
