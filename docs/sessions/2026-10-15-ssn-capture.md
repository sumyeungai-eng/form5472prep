## What shipped (on the branch)

The number is stored only as AES-256-GCM ciphertext `v1:<iv>:<tag>:<ct>` (random 12-byte IV, auth tag verified; wrong key or any tampering throws `PiiCryptoError`, never garbage).

## Contracts a future editor must respect
- **The SSN never leaves the server except as last4/masked and through the admin-website Reveal.** Not in customer/partner/v1 JSON, client props, emails or email attachments, logs (never log Prisma error objects on SSN writes — they echo the ciphertext), change-log JSON (masked only), Telegram/APNs, analytics, or the ITIN field.
- Exception by design: the generated IRS package PDF itself prints the SSN on 4b(1)/8b(1); it is served where packages already are (client portal PDF routes for the owner/partner/sign invite, the admin website PDF routes, R2, the IRS fax) — but never by the v1 (iOS) `/pdf` route and never as an email attachment.
- Decrypt only in `src/lib/pdf/packageInput.ts` and `revealOwnerSsn`. Never add SSN columns to `ADMIN_EDITABLE_FILING_FIELDS` (updateField logs raw before/after).
- New plaintext-carrying admin actions go in `WEB_ADMIN_ONLY_FILING_ACTIONS`, never in `FILING_ACTION_NAMES`.
- `toClientFiling` is a deny-list: any new secret column must be added to `SERVER_ONLY_FILING_FIELDS` / `STAFF_ONLY_FILING_FIELDS`.
- The pay path is untouched: entry is refused for DRAFT, so a package built at payment never has an SSN; `filingToPackageInput` never throws on the SSN.
