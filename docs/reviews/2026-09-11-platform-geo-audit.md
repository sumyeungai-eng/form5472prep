- **`article:modified_time` — MISSING.** `src/lib/blog.ts` frontmatter has an `updated` field (used for JSON-LD `dateModified` at `src/app/(marketing)/blog/[slug]/page.tsx:85`), but `generateMetadata` (lines 49-60) never passes `modifiedTime` into the `openGraph` object — only `publishedTime` (line 57). - twitter:title/description/image — correctly per-post here (this generateMetadata does set its own `twitter` block, lines 61-66) — the one page type that gets this right.
- **og:image is a per-post asset, but the URL 404s in production** — see critical bug below. It is a dynamically Satori-rendered title card (`src/app/(marketing)/blog/[slug]/opengraph-image.tsx`), distinct from the editorial illustration (`public/blog/{slug}.webp`, used only for JSON-LD `image` / the on-page hero, per `src/lib/blog.ts:112,271`).

### CRITICAL BUG: every blog post's og:image / twitter:image URL 404s
`curl -I https://www.form5472prep.com/blog/what-is-form-5472/opengraph-image` → **HTTP 404** (confirmed on 4 different slugs: `what-is-form-5472`, `amended-form-5472-correcting-errors`, `oregon-llc-foreign-owner-tax-filing`, `form-5472-vs-1120-f`, `stripe-paypal-wise-form-5472`). The meta tags correctly point at `/blog/{slug}/opengraph-image`, but the route resolves to the site's 404 page in production. Root cause: `src/app/(marketing)/blog/[slug]/opengraph-image.tsx` has **no `generateStaticParams`** (the sibling `page.tsx` does, at `src/app/(marketing)/blog/[slug]/page.tsx:36`) — Next.js image-metadata routes under a dynamic segment need their own params-generation to be included in the build/ISR output, so none of the ~127 per-post OG images are ever produced. **Every social share of every blog post on Facebook/LinkedIn/Slack/Twitter currently shows no image** (or a broken-link preview). Fix: add a `generateStaticParams` to `opengraph-image.tsx` mirroring `page.tsx:36`.

## Part B — RSS feed

- **Format:** RSS 2.0 with `atom:link rel="self"` — generated at `src/app/feed.xml/route.ts:1-58`.
- **Item count:** 127 `<item>` entries. `content/blog/*.md` has 129 files; the 2 excluded (`final-form-5472-closing-foreign-owned-llc`, `multiple-related-parties-form-5472`) have future `publishAt` dates (2026-09-21/28, after the "today" of 2026-09-11) and are correctly withheld by `isPubliclyAvailable()` (`src/lib/blog.ts:329-334`) — not a bug.
- **Links:** absolute (`https://www.form5472prep.com/blog/{slug}`). **pubDate:** present on all 127 items. **lastBuildDate:** present, matches the newest published post's date. **description:** present on channel + all items (128 total incl. channel).
- **Newest post check:** newest *publicly available* post (2026-09-11 batch) correctly appears; the two future-dated posts correctly do not.
- **No Atom `<updated>`** — expected, this is RSS 2.0 not Atom; not a defect.
- **Generated at:** `src/app/feed.xml/route.ts`.
- **Discoverability:**
  - `src/lib/llms.ts` — **no mention of `/feed.xml`** anywhere (grep, no matches). AI-crawler-facing `llms.txt` content omits the one asset built specifically to help crawlers find fresh posts fast.
  - `src/app/robots.ts` — references `sitemap.xml` only (line 62); **no feed reference**.
  - **Root layout DOES declare the feed** — `src/app/layout.tsx:43-46` sets `alternates.types["application/rss+xml"] = "/feed.xml"`. But it never reaches the rendered `<head>` on any page checked (home, pricing, blog, blog post, etc.) because **every page-level `metadata.alternates` (e.g. `src/app/(marketing)/page.tsx:94` `alternates: { canonical: "/" }`) replaces the whole `alternates` object rather than merging** — Next.js metadata does not deep-merge nested objects across layout→page, so the child's `alternates.canonical`-only object silently drops the parent's `types.rss` key. This is the root cause of the "no rss `<link>` in head" finding the architect already flagged. Fix: either add `types: { "application/rss+xml": "/feed.xml" }` to every page-level `alternates` block, or move the RSS declaration into a component that always renders (e.g. inject the `<link>` tag directly in `RootLayout`'s `<head>` rather than via the metadata `alternates` field).
