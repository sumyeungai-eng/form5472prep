## Decisions taken by the orchestrator (owner said "fix everything"; spec wins over older choices)

D1. Cover letter closing becomes **"Signed:"** (spec house rule 2), replacing "Sincerely," (2026-10-10). Still never any perjury wording on the cover letter.
D2. Extension **"not_sure" counts as NO extension for lateness** (spec item 4: 2025 with "Not sure" was late). So a "not sure" year gets an RCS. The amber "Extension unclear — confirm before fax" flag stays, and is ALSO raised as a pre-flight warning (item 14). Update `docs/filing-package-rules.md` + the F6 test accordingly.
D3. Customer free text (`FilingYearData.rcsWhyMissed`, `rcsWhenLearned`, legacy `Filing.reasonableCauseNarrative`) is the **customer's explanation**: shown to admin only, never rendered. The RCS cause narrative comes ONLY from a new admin field `rcsAdminNarrative`. No fallback.
D4. "When learned" becomes a structured admin date `rcsLearnedOn` (per year). The "still unaware when the [year] return was due on [date]" sentence is added for late years after the first late year when `rcsLearnedOn` > that year's due date. The empty-date warning applies only to late years after the first (where the sentence is needed).
D5. Paid preparer: per-order `paidPreparerMode` (null/"none" = no preparer, the default; "house" = fill the 1120 "Paid Preparer Use Only" block). House preparer details come from env vars (config, not code): `HOUSE_PREPARER_NAME`, `HOUSE_PREPARER_PTIN`, `HOUSE_PREPARER_FIRM_NAME`, `HOUSE_PREPARER_FIRM_EIN`, `HOUSE_PREPARER_FIRM_ADDRESS`, optional `HOUSE_PREPARER_PHONE`. If "house" is selected but config is incomplete → pre-flight error. Preparer signature, date and self-employed box stay blank (the existing place-signature step stamps the signature). Per-order `irsMayDiscussWithPreparer`: null (blank, default) / "yes" / "no".
D6. Part V citation → `Treas. Reg. sec. 1.6038A-2(b)(3)(xi)` (verified on law.cornell.edu: (b)(3)(xi) covers "any other transaction" of a §301.7701-2(c)(2)(vi) entity, "including contributions to and distributions from the entity").
D7. Small-corporation paragraph (item 5) uses the spec text verbatim. Per-year admin toggle `rcsSmallCorpParagraph` (null = auto: on when conditions met; true/false = admin override). "Registered-agent-only / no other U.S. presence" uses an existing field if one exists, else new `Filing.llcUsPresenceRegisteredAgentOnly Boolean?` (admin).
D8. A26 (item 2) evaluates the text that actually renders (now the admin narrative), names its source field (e.g. "Tax year 2024 → RCS narrative (admin)") and quotes each matched phrase (≤ ~80 chars). It also scans the customer explanation and reports matches there as context for the admin (warning, not error). Regex must also catch "no operating expenses, employees, or transactions".
D9. Blocked-phrase check (item 3: "?" addressed to us, "could you", "please review", "my objective", "minimal cost", "[CPA Name]") = pre-flight ERROR on any admin-authored or free text that renders into an IRS-facing document (RCS narrative, Part V/VI free-text notes).
D10. Regenerate while a reviewed PDF is current (`generatedPdfKey` contains `_reviewed_`): confirm dialog with the spec text; the regenerated draft is written to `${id}_unsigned.pdf` but `generatedPdfKey`, review approval and signature state are NOT changed; pre-flight re-runs; admin page offers "Download latest generated draft". Client signs `generatedPdfKey`; fax sends `signedPdfKey` (copied to `${id}_faxed.pdf`) — document this on the admin page and in the rules doc.
D11. Re-run pre-flight: new admin action `rerunPreflight` (generate package in memory, run checks, persist status/failures/warnings/checkedAt, no PDF write, change-log entry). Auto re-run after every change-logged `updateField` / `updateYearField` save and after Regenerate. Override handling on re-run: keep the recorded override only if the new failure IDs are a subset of the failure IDs that existed when it was recorded; otherwise clear it (change-logged).
D12. GENERATOR_VERSION → **2.3.0**. Follow the change procedure in `docs/filing-package-rules.md` (rule doc → assertion list → failing test → code → Implemented column).
D13. Schema: additive, nullable only, one migration `prisma/migrations/20261013120000_preflight_generator_spec/`. New staff-only year fields must be stripped from the customer-facing filing API (year rows are currently sent unfiltered).
D14. Out of scope (spec): IRS form templates, fax/Stripe/Resend, correcting the live order data.
