# Spec: auto-generate and fax Form 7004 for extension orders (2026-10-30)

Owner: "is our system able to auto generate the 7004 form after customer placed order?" → offered (1) generate, (2) fax from admin, (3) admin edit of order details, (4) "last updated" date on the landing page → "yes build everything".
Builds on the $79 service shipped in 1881925 (docs/reviews/2026-10-28-form-7004-service-spec.md, docs/sessions/2026-10-28-form-7004-service.md).

## IRS facts (verified 2026-10-28, i5472 + i7004)
- Form 7004 (Rev. December 2025), official PDF now at `public/forms/f7004.pdf` (downloaded from https://www.irs.gov/pub/irs-pdf/f7004.pdf; 1 page, 26 AcroForm fields f1_1…f1_18, c1_1…c1_4[0-4]; XFA stripped by pdf-lib — fine).
- For a foreign-owned U.S. DE (pro forma 1120 + 5472): Part I line 1 form code **12** (Form 1120); write **"Foreign-owned U.S. DE"** across the top; fax to **855-887-7737** (`IRS_FAX_NUMBER`, src/config/filingPackage.ts) at 300 DPI+ or mail to the Ogden PIN Unit — never the regular 7004 address. Must be filed by the return's original due date (15 April of Y+1 for calendar year Y, next business day if weekend/holiday — `src/lib/form7004.ts` already has the rule). No signature line.
- Lines to fill: name, EIN (identifying number), address (number/street/room, city, state, ZIP); line 1 form code "12"; line 5a calendar year (tax year Y); Part II lines 6 (tentative total tax) "0", 7 (total payments/credits) "0", 8 (balance due) "0". Leave other boxes (2, 3, 4, 5b reasons) unticked unless the field map proves they're needed. Map every field by geometry/tooltip and VERIFY VISUALLY: render the filled PDF to PNG (e.g. `qlmanage -t -s 1600 -o <dir> file.pdf` on macOS, or pdfjs in node) and look at it; record the mapping + how verified in the session log.

## Build
1. **Generator** `src/lib/pdf/form7004.ts`: `generateForm7004(order)` → PDF bytes. Fill via the repo's existing pdf-lib helpers (see `src/lib/pdf/fillForm.ts` toPdfSafe/flatten and the SS-4 generator used by `api/admin/applications/ein/[id]/generate-ss4` + `src/components/admin/Ss4Panel.tsx` — mirror that pattern). Stamp "Foreign-owned U.S. DE" across the top (like the 1120 stamp in generatePackage.ts). Flatten. Set PDF Title "Form 7004 – <LLC> – <year>", clear Author/Creator/Producer. Unit test: field values + stamp text present (extract with the repo's test helpers) + throws/flags nothing on blanks (missing data still generates, but the admin UI shows what's missing).
2. **Schema** (additive nullable migration `prisma/migrations/20261030120000_extension_autogen/`, hand-written SQL; never `migrate dev`): ExtensionApplication + `generatedPdfKey String?`, `generatedAt DateTime?`, `faxJobId String? @unique`, `faxStatus String?`, `faxSentAt DateTime?`, `faxDeliveredAt DateTime?`, `faxConfirmationKey String?`, `faxAttempts Int @default(0)`.
3. **Admin order page** (`src/app/admin/applications/extension/[id]/`):
   - Edit form for LLC name, EIN, street, city, state, ZIP, tax year, contact name/email (change-logged in adminNotes or a simple audit line; reuse the existing PATCH route, admin-auth). Customers can pay with missing data (repo rule) — staff fix it here.
   - "Generate Form 7004" → stores PDF (`<id>_7004.pdf` via the storage helper) + "View / Download" (admin-only PDF route, `Cache-Control: private, no-store`). Show missing-field warnings (no EIN / no name / no address / no tax year).
   - "Fax to IRS" (confirm dialog): sends the stored generated PDF to IRS_FAX_NUMBER via the existing fax module (`submitFax` in src/lib/fax.ts — reuse; don't fork Telnyx code). Server-side refusals with clear messages: no generated PDF; EIN or LLC name missing; tax year not ended yet (today < 1 Jan of Y+1 — we promised to fax after year end); due date passed (a late 7004 extends nothing); already faxed/in flight (duplicate guard — allow a deliberate re-send only with a written reason, like the filing re-fax guard). Status → PROCESSING while in flight.
4. **Delivery** — extend the Telnyx webhook (`src/app/api/telnyx-webhook/route.ts`) and the hourly poll (`src/app/api/cron/fax-status-poll/route.ts`) to recognise faxJobIds belonging to ExtensionApplication (today they look up Filing only). On delivered: store a fax transmission receipt PDF (reuse `generateFaxReceiptPdf` like src/lib/fax/finalize.ts), set faxDeliveredAt, status COMPLETED, email the customer (new `sendExtensionFaxedEmail`, attaching the receipt AND a copy of the faxed 7004; copy: transmission evidence, not IRS acceptance; the extension moves the return deadline to 15 October; no guarantees), admin email + Telegram. On failure: faxStatus failed, status back to IN_REVIEW, admin email + Telegram; the customer gets nothing. Keep Filing fax behaviour byte-for-byte unchanged (add a branch; existing faxFlow tests must still pass).
5. **Landing page freshness**: visible "Last updated <date>" on /form-7004-extension + `dateModified` in its JSON-LD (constant like other pages' LAST_REVIEWED).
